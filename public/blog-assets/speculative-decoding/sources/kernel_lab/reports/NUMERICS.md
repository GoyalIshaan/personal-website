# Numerical contract and independent gates

This backend is BF16 inference, not bit-exact unmodified Hugging Face. Both models
having BF16 weights does not ensure matching AR/block predictions: GEMM kernels,
attention reductions, intermediate rounding, and near-tied logits matter.

## Fixed contract

- Projection plans are frozen by role, never selected from query count. MMA uses
  physical M=16. The SIMT candidate computes each query independently. The vendor
  candidate pads every call to physical M=16. All still require width tests.
- Split-K uses FP32 partials and a fixed ascending split merge, without atomics.
  Changing splits, BK, or plan family changes the numerical backend.
- A linear result rounds to BF16 before residual addition. The residual sum
  rounds to BF16 before the FP32 RMS reduction. Normalized values round to BF16
  before multiplying the BF16 RMS weight. Projection/norm epilogue fusion retains
  these boundaries explicitly.
- RoPE uses tables generated by pinned HF. Each product rounds to BF16 before
  adding the two products. Fusion is disabled across these boundaries.
- Gate/up rows are interleaved during one-time weight packing. Gate and up
  projections round to BF16; SiLU rounds to BF16 before multiplying up.
- GQA computes one time query per CTA and groups Q heads over their shared KV
  head. Split/chunk sizes and the merge schedule are fixed. Probabilities round
  to BF16 for the PV dot; softmax state and accumulators are FP32.
- Head top-two ranks BF16-rounded logits, with smaller token IDs breaking ties,
  including across vocabulary tiles and the partially filled final tile.
  The optional target-only top-one path uses the same matrix plan, rounding and
  tie order; it must equal the first top-two token. Draft scouts still use top-two.
- K and V strides are independent in every kernel. No future slot, even one
  containing NaN, may be loaded into a live attention dot.

The finite-input contract does not define useful generation for NaN/Inf model
states. Independent audits fail if any audited logits are nonfinite.

## Gates before timing

1. Primitive comparisons against independent PyTorch operations; different K/V
   strides; poisoned future KV; cross-tile head ties; CUDA device guard tests.
2. Exact equality between the token-only head and a materialized head using the
   same arithmetic plan. Exact fused-vs-separate projection/residual/norm results.
3. Independent unmodified HF one-shot and cached teacher-forced logits, captured
   before the source model is consumed. Initial gates: finite; relative L2 <=.05;
   softmax total variation <=.02; same top-one at these checkpoints. These are a
   small regression audit, not a model-quality guarantee. A near-tie gate failure
   requires inspecting margins and the arithmetic; it is not automatically a
   proof of a kernel bug. Any threshold revision needs a journal event.
4. Exact native width-one AR vs AR chunks and SD/SSD, including forced early EOS,
   output cap, request reuse, partial rejection, full acceptance, scout hits and
   misses. Symbolic prefix-dependent models exercise state transitions alongside
   real small Qwen models and real pretrained-model gates.
5. Warm every measured path, then require exact native-AR tokens in every timed
   repetition. Save actual token IDs, not just text or requested token count.

The root v2 history documents why self-consistency alone is insufficient: its
first invariant one-shot audit found a V-stride error even though cached AR/SD
matched. These new independent layout tests exist specifically for that failure.

The 0.5B draft and 7B/32B targets have different padded vocabulary dimensions. The
benchmark checks equal tokenizer mappings, then, if necessary, adds zero INPUT
embedding rows to the draft so any target token can be embedded. Existing input
rows and the draft output head remain unchanged. This only extends the approximate
draft, and the extension count is recorded. The target is untouched.

## Pinned-stack device compatibility

Batch E exposed an HF RoPE call reaching a PyTorch-native Triton BMM launch on the wrong current GPU. The context-only `DeviceGuardedRoPE` wrapper calls the original HF implementation on the input device for both oracle and preserved v2 models. The new adapter also guards its own table construction and public diagnostic entry points. This changes device selection, not formulas, precision, weight values or acceptance tolerances. Receipts explicitly record the wrapper; independent-HF means its numerical implementation is independent, not that no compatibility wrapper is installed. See [batch E](BATCH_E.md) and the raw traceback.


## Reduction-policy experiment after batch F

F recorded BF16 vendor reduced-precision reduction enabled; its largest TV was0.0245623 at one point although every tested top token matched. The next study retains L2<=0.05, TV<=0.02 and matching top1. It compares HF full/reduced reduction on identical forced prefixes and uses full vendor reductions for new candidate eligibility and all later comparison backends. This is an explicit benchmark-policy change, not a tolerance change or a promise of bitwise HF equivalence. Both modes, raw failing logits, intermediate operator errors and plan choices are preserved. Fixed query shape and exact native-AR sequence gates remain mandatory.

G falsified the reduction-policy hypothesis at the tested prefixes: original HF
logits were exactly equal under both settings. The prepared next revision uses
original-HF-compatible dense prefill, with separate projection GEMMs, original
BF16 rounding boundaries and causal unmasked SDPA. It prefills the complete
prompt to preserve the independent reference's GEMM batch shape, then overwrites
the last input on the first decode. This changes initialization arithmetic, not
the fixed decode contract or tolerances. Dense packing/unpacking costs remain
inside measured prefill and end-to-end latency. Legacy and partial repairs are
retained as explicit diagnostic variants; no old result is relabeled.


## Diagnostic runtime exception after H

Default evaluation still stops at a failed independent HF audit. The explicit
`--diagnostic-allow-hf-audit-failure` flag permits provisional runtime diagnosis
with the same failed audit and unchanged thresholds saved. Such configurations
receive `diagnostic_completed` summaries and diagnostic-only rows; the validated
comparison summarizer excludes them, covered by a CPU regression. Width
invariance and exact native-AR sequences remain hard timing gates. This flag is
not independent numerical validation, a quality result or permission to relabel
failed rows as passing. H identified exact prefill but remaining decode drift;
profiling is needed to choose worthwhile runtime/kernel work.
